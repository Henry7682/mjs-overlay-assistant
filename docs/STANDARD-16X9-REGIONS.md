# 16:9 客户区识别区域

开发分支以 f6c77da 为基线，不包含 b142f71 的自动扩区、位置记忆和追加 OCR 流程。旧分支及证据保留。本轮没有新发行。

## 坐标基准与运行边界

运行时使用现有 WGC 客户区截图，不按显示器分辨率或带标题栏的窗口截图定位。本轮接受客户区高与 `宽 × 9/16` 相差不超过2像素的输入；其他比例在设置状态中提示调整窗口，暂停识别和查询。已有本局攻略缓存及用户校准保留，恢复有效画面后继续识别。不自动裁黑边、拉伸图片，也不修改游戏分辨率。

旧模板中的候选牌阵参考2559×1334客户区。该比例不是16:9。居中牌阵按画面高度等比缩放：`s = h/1334; x' = w/2 + (x-2559/2)*s; y' = y*s`。统一转换层只计算并缓存坐标，不缩放整帧。战场姓名仍使用经过回放验证的客户区比例位置；主公左侧面板不跟随居中候选转换。

姓名初始余量为1080p下水平6像素、竖直8像素，其他16:9尺寸等比变化。战场旧模板已有余量，避免重复扩张。人工校准是实际客户区坐标，优先使用且不重复转换。公开库仍保留旧比例离线回归能力，但运行入口本轮仅接受16:9。

## 修正范围

- 普通楚汉八人、巅峰十四人禁将、巅峰6–12人选将及八人身份候选：转换居中模板，保留槽位编号、词典、置信度和连续两帧确认。
- 巅峰/身份牌阵的几何宽度、间距和位置检查使用同一转换；不能只移动姓名框，漏改布局判断。
- 入口文字与高亮颜色分别裁剪，保留双重确认；“爭/争”仅作模式标签的文字归一化。
- 禁将座次区域与选将分开；战斗阵营字条和座次增加合理边界。未能确认的座次仍未知。
- 姓名字形核验仍接收原姓名条宽度，不把新增OCR余量误当作字形图案。
- 小程序操作流程、预算和攻略缓存规则保持；非16:9输入只取消当前自动操作、隐藏过期画面，不删除本局有效缓存。
- “主公＋六候选”在牌阵数量、位置、宽度都匹配时直接使用已覆盖的模板，免去两次大范围定位；缺牌、额外牌或明显偏移时仍走原定位兜底。没有增加OCR复核轮数。

## 私人素材回放

原图、客户区、姓名标注、区域预览和计时报告应保存在仓库外的私人证据目录。原图归档先写迁移清单，记录SHA256并复验；不把完整聊天、昵称截图放进tests或分发。

`tools/replay_regions.py` 接受外置JSON，包含 `samples` 数组。每项包括 `id`、相对 `image` 路径、`mode`、预期 `scene`、`heroes`、入口的 `entry`（其他场景null）；可附 `name_bounds` 客户区像素框。姓名必须人工核对，自动检测的字框需视检，不能将待测程序输出直接当作正确答案。

```powershell
.\.venv\Scripts\python.exe tools/replay_regions.py <私人标注.json> --output <私人结果目录> --baseline-ref f6c77da --rounds 5 --perturb
```

比较基线、仅修坐标、坐标加余量三组；每轮交错顺序，输出首次处理、相同帧缓存、单像素变化触发处理的耗时与OCR次数。单像素变化不代表完整动画，±4/±6像素姓名偏移与旧字形放大均属合成测试。基线模块从指定提交只读加载，不切换工作树，不启动游戏或小程序。
