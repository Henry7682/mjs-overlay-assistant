# 1.1.0 自动更新与数据维护执行记录

## 产品目标与已确认方案

玩家从最外层 launch.cmd 启动，自动检查可达的新版；官方榜单与内置组合库分别更新，失败保留现有可用数据。软件使用新版本1.1.0公开测试版，不覆盖历史版本。默认内置组合库，保留用户明确的在线查询选择。

2026-11-13检查：GitHub发行1.0.6、Gitee发行1.0.5；两份主清单尚无对应Gitee附件地址。GitHub组合库为11月4日641篇，Gitee数据分支清单404；TapTap官方列表三页返回网页验证内容。不能把HTTP200或任务执行过当成最新数据确认。

维护端使用本机每日05:00定时任务，错过时间后在账号登录时补跑，不唤醒电脑、不依赖云定时。用户负责Gitee发行附件上传，agent随后核对地址、签名同步及匿名国内更新验收。Gitee附件未上传前，材料准备和通道启用分别记录。

## 实施与验证原则

- 软件、榜单、组合库分别显示检查状态、成功时间、来源与立即重试。网络失败按5分钟、30分钟、2小时、之后6小时退避并少量抖动，不清空历史成功记录。
- 官方数量按每个模式每期图片确定，既允许增加也允许有证据的减少。两榜连续排名、姓名、排序和模式周期校验仍保留。增加已支持深色双栏图的表格末尾边界证据，未知布局、截尾、疑点保留旧数据，不按已读最大排名自证完整。
- 官方签名备用通道使用 boards-data 分支，和 jiangce-data 组合库通道分别维护。保留官方出处，维护者签名不代表官方授权背书；组合网站单将胜率不用于官方榜单。
- 新姓名双榜核验后纳入运行时词典，保留用户纠错。组合库本局固定快照，下局启用更新；榜单OCR等待选将与配阵空闲。
- 客户端独立发现GitHub/Gitee版本，落后镜像可升级到比本地新的可达版本，禁止降级。校验错误、配置破坏、启动失败和私人数据泄露属于发布阻断项。

## 维护者操作

源码锁定环境中运行 `python tools/maintain_data.py --publish`，检查私人 `.research/maintenance/status.json`。使用 `tools/install-data-task.ps1` 注册当前登录账号任务。私钥仍在仓库外；需要两个Git远端的正常写入凭据，任务不询问或记录密码。

维护顺序：采集归档、核验、生成不可变数据、签名、上传、匿名回读。单渠道失败保留另一渠道成功结果。原始截图、日志和运行配置不公开分发。

## 发布与验收

主题分支提交推送、PR、syntax/windows通过后merge commit合入main；干净标签构建v1.1.0，签名更新清单另经PR启用。QQ群ZIP与正式完整便携ZIP保持一致。Gitee提供每卷不超过90MB的上传材料，上传后才确认国内路径。

必测：变动人数与新增姓名、两榜同时截尾、跨年与同周期修订、错模式、验证页、坏签名、部分失败、断网与低速换源、跨日重试、旧版升级与回退、配置保留、离线新解压启动、四模式回归。Win10、真实14人选将、多分辨率和完整实战仍须单列，不由单元或截图回放代替。
