# 相册文件框回归与 Windows 10 核查

状态：1.0.5 后源码修复，未发布。Windows 10 实机尚待验收。

## 本机回归原因

运行中的 1.0.5 能找到相册按钮并打开文件框，但等待至 15 秒超时。现场同一文件框包含控件 1、2、1148，没有 1152。pywin32 的 GetDlgItem 对不存在的控件抛出错误 1421；原代码用一个集合推导式读取四个编号，异常导致整段就绪判断跳过。模拟测试之前返回 0，没覆盖真实封装的异常行为。

修复逐个容忍缺失的可选控件；1148、1152 是替代候选，不要求同时存在。递归枚举处理嵌套子控件和已销毁的子项。提交时也从文件框后代控件中唯一定位可见、启用的 IDOK 按钮，不再要求它是第一层子控件。

仍只识别绑定小程序拥有的标准文件框；文件名 Edit 必须归属已知文件名宿主，不能误用搜索框。不依赖中文“打开”文字、桌面绝对坐标或文件夹默认位置。写入绝对 PNG 路径后回读核对，失败保持明确错误，不向不确定控件输入。

## 微软官方资料核查

- [GetDlgItem](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getdlgitem)：最低 Windows 2000；原生函数对不存在的控件返回 NULL，不能据此假设 Python 封装也返回零。
- [EnumChildWindows](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-enumchildwindows)：最低 Windows 2000，并会枚举后代子窗口；支持当前嵌套控件路线。
- [Common Item Dialog](https://learn.microsoft.com/en-us/windows/win32/shell/common-file-dialog)：Vista 开始使用，Win10/Win11 均有；不是 Win11 独有文件选择器。文档并未保证第三方对话框在所有版本有相同内部层级或控件编号。
- [BM_CLICK](https://learn.microsoft.com/en-us/windows/win32/controls/bm-click)：支持 Vista 及以后；非活动对话框可能不响应。保留现有前台/目标窗口检查，不盲目投递到其他程序。
- [SendMessageW](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendmessagew)：跨进程消息受 UIPI 限制，低权限不能任意控制高完整性进程。权限差异是 Win10/Win11 共有条件，不应误判为控件编号或路径问题；不能承诺管理员权限能修复所有页面故障。

以上接口可在 Windows 10 调用，本次没有引入 Win11 专用 API。接口兼容不等于已完成不同微信版本、权限和显示设置的实测。

## 证据与边界

- 同一个真实文件框：修复前 ready 为空、owned 有窗口；修复后 ready 正确包含该窗口。
- 实际小程序组件：清理残留文件框、清空旧候选、打开相册、写入 PNG、提交均完成；8.80 秒提交，9.92 秒进入图片识别等待。之后样本出现人工确认，测试等待结束；这只证明导图恢复，不表示最终攻略获取通过。
- 单元覆盖缺失 1148/1152 时的 1421 异常、嵌套宿主、搜索框排除、嵌套打开按钮、歧义、中文空格路径。新增嵌套按钮修复尚无独立实机复测。
- 待 Win10 实测：默认/嵌套文件框、中文空格目录、100%/125%/150% 缩放、不同微信版本、同权限/权限不匹配、连续上传、残留窗口恢复及完整配阵。保留 T30/T35/Win10 待办，不把 Win11 的组件成功写成 Win10 验收。
