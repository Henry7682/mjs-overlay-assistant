# 巅峰配阵整链路提速与空点击恢复

本轮基于1.0.4后的开发源码010855f。目标是尽早给玩家提供已经确认的攻略；不是把部分结果宣称为完整查询。延续[历史性能调查](../PERFORMANCE-2026-10-28.md)，不把波动根因直接归为Windows或某一次提交。

## 提交审查

- b7740e7把“名单包含目标”改为“名单已按搜索词过滤”，没有增加一次UIA读取或固定等待；旧名单仍未刷新时会继续等待。撤去这一条件的单轮对照没有变快，因此保留对东方朔旧列表误点的防护。
- 73bf9dd避免一名OCR波动重置整池等待，但确认后的额外1秒属于整链路耗时。本轮只保留逐名证据与至少两名候选要求，直接复用识别器原有两帧确认，不再叠加1秒等待。未确认名字不能触发；普通楚汉截图门禁不变。
- 69f885d只改变浮窗Z序，没有增加UIA、OCR或查询等待，继续保留；此次没有通过重叠区域的实战视觉验收关闭T44。

## 改动

1. 输入前仍重置公开筛选，但不再清空搜索并反复读取完整目录。直接搜索当前名单，不因完整目录尚未加载而整条失败。
2. 去掉每次写入搜索前的远程Value读取；仍使用公开Value接口写入，并核验实际候选和已选名单。
3. 选入失败先重新读取已选状态，避免对已经迟到生效的点击重复切换；重新定位再试一次。单名头像暂不可用或重试后仍没选入，记录缺项、继续其他候选；非本次候选、已确认名单减少、取消和窗口异常不能当作普通空点击吞掉。
4. 每名确认后继续回传阶段性攻略，保留已确认的子集；复用最后一次输入核验结果，去掉重复整页读取。首次为空的结果另做新鲜回读，避免把尚未更新的结果当作全局无组合。
5. 巅峰结果位置和攻略数连续不再变化时，减少重复滚动观察，但仍明确标为“末尾未确认”，不将重复页面当完整证据。普通楚汉滚动条件不变。
6. 30秒软目标从自动查询首次识别禁将/选将的客户区帧时间计算，包含本地确认、连接、进程启动和切窗；预留4秒读结果、1秒返回。临近目标不继续扩充名单，返回可用部分并列出未提交武将。底层40秒硬上限保留，以容纳无法中断的远程调用；并不保证每次都能在30秒内完成。
7. 用户很晚才打开小程序时仍给一次最多受硬上限约束的短时机会（至少10秒软目标）；手动重查重新计算目标，不继承上一请求过期计时。计时字段不参与请求指纹，不使缓存失效。
8. 日志记录首次识别选将、发起延迟、首批攻略与结束的整链路时间，不增加OCR或UIA扫描。
